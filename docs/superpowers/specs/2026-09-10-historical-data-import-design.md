# 历史比赛与市场数据导入设计

## 1. 文档状态

- 日期：2026-09-10
- 状态：设计已确认，等待实施计划
- 模块：历史比赛与市场数据导入
- 首个数据源：Football-Data
- 数据库：DuckDB

## 2. 目标

建立可重复执行、可中断恢复、可扩展数据源的历史数据导入管道。第一版支持 Football-Data 当前提供的全部公开联赛，默认导入最近 5 个完整赛季，并将比赛结果与可验证的历史市场赔率写入统一数据库。

本模块为后续实体匹配、特征工程、基线模型和时间回测提供数据，不训练或运行任何预测模型。

## 3. 数据来源与边界

### 3.1 第一版数据来源

Football-Data 提供 CSV 格式的历史数据。第一版导入以下字段：

- 联赛和赛季；
- 比赛日期与开赛时间；
- 主队与客队名称；
- 半场主客队进球；
- 全场主客队进球；
- 胜平负赛前及收盘赔率；
- 2.5 球大小球赔率；
- 亚洲让球盘口及对应赔率；
- 数据来源、下载时间与可用时间。

不同联赛、赛季的字段完整性可能不同。缺少赔率不影响比赛结果导入。

### 3.2 暂不导入

- 射门、角球、犯规和红黄牌等比赛统计；
- 阵容、伤停和球员事件；
- 无明确授权或来源不可靠的历史数据；
- 无法从当前来源验证的竞彩足球历史全玩法 SP。

### 3.3 竞彩足球玩法兼容

数据库需要预留以下市场类型，但第一版只写入来源实际提供的选项：

- 胜平负；
- 让球胜平负；
- 比分；
- 总进球 0 至 7+；
- 半全场九种组合；
- 大小球；
- 亚洲让球。

不得把模型推导概率或国际市场赔率伪装成竞彩足球 SP。每条市场数据必须保留来源、提供方、采集时间和可用时间。

## 4. 数据库设计

现有 `market_snapshots` 的主、平、客固定列无法表示比分、总进球和半全场等多选项市场。数据库结构版本升级时新增通用市场表。

### 4.1 `market_snapshots`

一行表示某场比赛在某个时间点、某个提供方的一个市场快照，核心字段包括：

- 快照 ID；
- 比赛 ID；
- 数据来源与赔率提供方；
- 市场类型；
- 盘口参数；
- 快照阶段，如赛前或收盘；
- 采集时间；
- 数据可用时间。

### 4.2 `market_outcomes`

一行表示一个市场快照中的一个可选结果：

- 市场快照 ID；
- 选项代码；
- 原始赔率值；
- 可选的标准化概率；
- 原始字段名称，用于追溯来源。

选项代码示例：

| 市场 | 选项代码示例 |
|---|---|
| 胜平负 | `home`、`draw`、`away` |
| 总进球 | `0`、`1`、`2`、`3`、`4`、`5`、`6`、`7_plus` |
| 半全场 | `home_home`、`home_draw`、`home_away` 等九种组合 |
| 比分 | `1_0`、`1_1`、`other_home`、`other_draw`、`other_away` |
| 大小球 | `over_2_5`、`under_2_5` |
| 亚洲让球 | `home`、`away`，盘口保存在快照层 |

市场类型和选项代码由应用层枚举校验，避免数据库结构因新增玩法频繁变化。

### 4.3 时间语义与防止未来信息泄漏

- `kickoff_at`：比赛实际开始时间；
- `captured_at`：来源实际采集赔率的时间；
- `available_at`：该条数据最早可被回测或线上计算使用的时间；
- `stage`：`pre_match`（赛前）或 `closing`（收盘）；
- `time_precision`：时间证据精度，取 `exact`、`date_only` 或 `kickoff_bound`。

CSV 下载时间只记录文件获取行为，不能作为文件内每条历史赔率的
`captured_at` 或 `available_at`。来源提供准确采集时间时，两个时间使用该值并标记
`exact`；只有日期时采用该日期结束时刻等保守边界并标记 `date_only`；Football-Data
这类只给历史收盘赔率而没有采集时间的文件，统一设置
`captured_at = available_at = kickoff_at`、`stage = closing`、
`time_precision = kickoff_bound`。因此，开球前的回测不能读取这些记录，避免未来信息泄漏。
从 version 1（结构版本 1）迁移且无法还原真实来源的旧快照使用
`source = legacy_unknown`，不得用赔率提供方名称代替数据来源。

### 4.4 导入运行记录

新增导入运行与文件级结果记录，至少保存：

- 运行状态与起止时间；
- 请求的联赛、赛季和数据源；
- 下载、导入、重复、跳过及失败数量；
- 每个文件的地址、保存路径、校验值和处理状态；
- 可公开展示的错误摘要。

## 5. 组件设计

### 5.1 数据源目录

维护受支持的国家、联赛代码、赛季格式和下载地址模板。默认选择最近 5 个完整赛季，同时允许调用方显式指定联赛和赛季。

目录必须由配置驱动，不能把每个下载地址散落在业务代码中。

### 5.2 下载器

职责：

- 设置连接和读取超时；
- 对临时网络错误进行有限次数重试；
- 将文件保存在 `data/raw/football_data/`；
- 复用校验值一致的已有文件；
- 验证 HTTP 状态、内容类型、文件大小和 CSV 表头；
- 防止 HTML 错误页被当作 CSV 导入。

### 5.3 CSV 解析器

解析器只负责将来源字段转换为统一的中间记录，不直接访问数据库。它需要兼容不同年份列名变化，并执行：

- 日期和时间解析；
- 整数比分校验；
- 半场、全场结果一致性校验；
- 赔率正数校验；
- 空值标准化；
- 原始行号保留。

### 5.4 实体标准化

第一版以数据源联赛代码生成赛事标识，以数据源中的球队名称建立或查找标准球队，并写入 `team_aliases`。

名称标准化只处理大小写、首尾空格、重复空白和常见 Unicode 差异，不自动猜测含义不同的球队名称。未来接入体彩中文名时再增加人工审核和跨来源实体匹配。

### 5.5 数据库导入器

每个源文件在独立事务中处理：

1. 创建或读取赛事；
2. 创建或读取主客队与别名；
3. 按来源比赛标识写入比赛；
4. 写入可用的市场快照及选项；
5. 更新文件级导入结果。

同一个源文件重复运行必须得到相同数据库结果，不产生重复比赛或赔率。

### 5.6 导入协调器

协调器按联赛和赛季逐个调度文件。一个文件失败时记录错误并继续其他文件，最终状态可为：

- `completed`：全部成功；
- `completed_with_errors`：部分成功；
- `failed`：没有文件成功或发生系统级错误。

## 6. 数据流

```text
联赛与赛季清单
  -> 下载并校验原始 CSV
  -> 解析为统一中间记录
  -> 标准化赛事、球队和别名
  -> 事务写入比赛与市场数据
  -> 保存文件级和运行级报告
```

原始文件、处理中间产物和 DuckDB 数据库均属于本地数据，不提交到 Git。

## 7. API 设计

### 7.1 `POST /api/data/import`

触发一次导入。请求可指定数据源、联赛代码和赛季；未指定时使用 Football-Data 全部公开联赛与最近 5 个完整赛季。

第一版本地应用可以同步执行，但接口返回中必须包含唯一运行 ID，以便以后平滑迁移为后台任务。

### 7.2 `GET /api/data/imports/latest`

返回最近一次导入的状态、时间、范围、统计和有限的错误摘要，不返回内部堆栈或本机敏感路径。

### 7.3 `GET /api/data/summary`

返回当前赛事、球队、比赛、市场快照、市场选项数量，以及最近数据时间和最近成功导入时间。

## 8. 错误处理与恢复

- 下载失败：有限次数重试，失败后继续下一个文件；
- 文件损坏：拒绝导入并记录校验错误；
- 字段缺失：缺少比赛核心字段时跳过该行，缺少赔率时只导入比赛；
- 解析异常：记录文件、行号和安全错误代码；
- 数据库异常：回滚当前文件，不影响已提交文件；
- 重复运行：通过稳定来源标识和唯一约束跳过重复数据；
- 中断恢复：复用已下载文件与已完成文件状态；
- 来源结构变化：未知必要列导致该文件失败，不静默产生错误映射。

## 9. 测试策略

自动测试使用仓库内的小型固定样例，不依赖网络。测试至少覆盖：

- 新旧字段名称解析；
- 日期、时间、比分和赔率校验；
- 缺少赔率时仍导入比赛；
- 球队别名标准化；
- 市场快照和选项映射；
- 同一文件重复导入的幂等性；
- 单个文件失败不影响其他文件；
- 事务失败回滚；
- 三个 API 的正常与错误响应；
- 下载器通过模拟 HTTP 响应验证超时、重试和错误内容拒绝。

网络数据下载作为人工或单独集成检查，不作为常规测试通过的必要条件。

## 10. 安全、许可与可追溯性

- 只使用公开且用途与项目相符的数据；
- README 中注明 Football-Data 来源和使用边界；
- 不提交原始数据、数据库文件或秘密配置；
- 不绕过登录、付费墙、验证码或访问限制；
- 不把一个来源的赔率标记成另一个来源；
- 每条比赛和市场记录保留来源标识与可用时间，防止回测中的未来信息泄漏。

## 11. 验收标准

1. 可配置导入 Football-Data 全部公开联赛的最近 5 个完整赛季。
2. 一个联赛或文件失败时，其他文件仍可继续处理。
3. 重复执行不会产生重复比赛或市场数据。
4. 缺少赔率的比赛仍能正确导入。
5. 胜平负、2.5 球大小球和亚洲让球可写入通用市场结构。
6. 数据库结构可容纳未来竞彩足球胜平负、让球胜平负、比分、总进球和半全场 SP。
7. API 能触发导入并查看最近状态与数据摘要。
8. 自动测试不依赖外部网络并全部通过。
9. 不实现预测模型、特征工程或自动购票功能。
